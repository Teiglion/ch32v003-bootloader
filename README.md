# UART Bootloader для CH32V003

Русский | [English](README.en.md)

Для первоначальной установки используйте WCH-LinkE или совместимый программатор (при разработке использовался Ardulink). После установки загрузчика пользовательские `.bin` можно записывать через UART.

При включении питания загрузчик проверяет PC0:
- HIGH — ожидание прошивки по UART;
- LOW — запуск пользовательского приложения.

На использованной отладочной плате PC0 подключён к кнопке.

## Возможности

- Обмен через USART1 со скоростью 115200 бод.
- Передача прошивки блоками до 64 байт.
- Проверка размера образа относительно размеров памяти чипа.
- CRC32-проверка каждого блока перед записью.
- Итоговая CRC32-проверка образа, прочитанного из Flash.
- Ответы с результатами операций и кодами ошибок.
- Автоматический запуск приложения после успешного обновления.
Загрузчик проверяет целостность переданных и записанных данных, но не функциональную корректность приложения. Автоматический откат к предыдущей прошивке не предусмотрен.

## Организация памяти

| Область | Физический адрес | Размер | Назначение |
|---|---|---|---|
| BOOT/SYSTEM | `0x1FFFF000` | 1920 байт | Загрузчик |
| USER Flash | `0x08000000` | 16 Кбайт | Пользовательское приложение |
| RAM | `0x20000000` | 2 Кбайт | Оперативная память |

BOOT/SYSTEM — отдельная область: загрузчик не занимает начало пользовательской Flash.
При запуске выбранная область Flash отображается на адрес `0x00000000`. Поэтому linker script загрузчика использует:

```ld
FLASH (rx) : ORIGIN = 0x00000000, LENGTH = 1920
```
Это адрес исполнения, а не физический адрес установки загрузчика. Для записи в BOOT/SYSTEM используется цель `bootloader` в `minichlink`. Перед прошивкой отредактируйте `MINICHLINK` и `PROGRAMMER` в Makefile: укажите путь к `minichlink`, используемый программатор и порт подключения.
Образ приложения записывается начиная с `0x08000000`. Он должен быть подготовлен для исполнения при отображении USER Flash на `0x00000000` и содержать собственный startup-код.

## Настройка стартовой области

Для автоматического запуска загрузчика должен быть выбран старт из BOOT:

```text
START_MODE = 1
```

Не переключайте `START_MODE` в option bytes на старт из USER, если хотите пользоваться возможностями загрузчика - при старте из USER приложение запускается напрямую: загрузчик и проверка кнопки обходятся.
Если настройка изменена, восстановите старт из BOOT с помощью программатора. Перезаписывать сам загрузчик не требуется, если его код сохранился. Одна только запись бинарника в BOOT/SYSTEM не заменяет проверку настройки `START_MODE`, так как она хранится в энергонезависимой памяти чипа.

## UART

| Сигнал CH32V003 | Назначение |
|---|---|
| PD5 | TX USART1 |
| PD6 | RX USART1 |

UART подключается перекрёстно:

```text
TX адаптера  --> PD6 / RX микроконтроллера
RX адаптера  <-- PD5 / TX микроконтроллера
GND          --- GND
```

Параметры обмена:

```text
115200 бод
8 бит данных
Без контроля чётности
1 стоп-бит
Без аппаратного управления потоком
```

## Протокол

Обмен бинарный. Многобайтовые числа передаются младшим байтом вперёд: little-endian.

### Команды хоста

| Код | Название | Назначение |
|---|---|---|
| `0x01` | BEGIN | Начало обновления |
| `0x02` | DATA | Начало передачи блоков |
| `0x03` | END | Завершение передачи |

### Заголовок

```text
BEGIN       1 байт
IMAGE_SIZE  4 байта
IMAGE_CRC   4 байта
```

Загрузчик проверяет размер образа и стирает необходимые области Flash. После успешной подготовки отправляет:

```text
READY 00 00
```

### Передача блоков

Команда `DATA` передаётся один раз перед первым блоком.

Каждый блок содержит:

```text
PAGE_NUMBER  2 байта
PAYLOAD      до 64 байт
PAGE_CRC     4 байта
```

Нумерация начинается с нуля. Ожидается строго последовательная передача блоков.

Размер последнего блока определяется общим размером образа. Его незанятая часть перед записью дополняется значениями `0xFF`.

CRC последнего блока рассчитывается только по полезным данным, без дополнения.

После успешной записи блока загрузчик отвечает:

```text
ACK PAGE_NUMBER
```

### Завершение

После всех блоков хост отправляет `END`.

Загрузчик рассчитывает CRC32 образа непосредственно по данным в пользовательской Flash. В расчёт входят только `IMAGE_SIZE` байт.

При совпадении с `IMAGE_CRC` отправляется:

```text
DONE 00 00
```

### Формат ответа

Каждый ответ состоит из трёх байтов:

```text
STATUS  VALUE_LOW  VALUE_HIGH
```

Для `ACK` поле `VALUE` содержит номер блока. Для ошибок значение зависит от места отказа: в некоторых случаях передаётся номер блока, в других — ноль.

| Код | Статус | Значение |
|---|---|---|
| `0x01` | READY | Flash подготовлена к приёму |
| `0x02` | ACK | Блок проверен и записан |
| `0x03` | DONE | Весь образ проверен |
| `0x04` | BAD_PARAMS | Ошибка параметров или номера блока |
| `0x05` | BAD_CRC | Несовпадение CRC |
| `0x06` | FLASH_ERROR | Ошибка операции с Flash |
| `0x07` | BAD_STATE | Неожиданная команда |

### CRC32

Для блоков и всего образа используются одинаковые параметры:

```text
Начальное значение: 0xFFFFFFFF
Отражённый полином:  0xEDB88320
Финальный XOR:      0xFFFFFFFF
```

CRC передаётся в формате little-endian.

### Нештатные ситуации
После ошибки или прерывания передачи заново запустите устройство с HIGH на PC0 и повторите прошивку. Повторный запуск хостовой программы сам по себе не перезапускает загрузчик.
